## Deviations from the brief, and decisions this plan takes

**D1 — Task 9 touches the platform, and shared contract §13.4 says plan 5 "touches no code".**
The same §13.4 bullet also says *"the enum and its comment move with the spec"*. Both cannot be
literally true. The ruling taken here: **"touches no code" means "changes no behaviour"**.
`FourEyesAction` is unmapped vocabulary — `EnumWireAlgorithmDivergenceTests` says so in its own
comment (*"`BankAccountStatus`, `FourEyesAction` and `ConnectionStatus` are never used as an EF-mapped
property … so `EnumToScreamingSnakeConverter<TEnum>` never runs on them"*), nothing constructs a
`FourEyesAction`, and `customer.approval_request` does not exist in any migration. Removing an arm
changes two pinned arrays and nothing else. It is a vocabulary edit, in its own commit, in its own
task, last but one.

**D2 — this plan edits `specs/site/build.mjs`, which the brief did not ask for.**
`build.mjs` parses open questions with `/^\|\s*\*\*(OQ-\d\d)\*\*\s*\|…/` — **exactly two digits**.
`OQ-105` does not match, so the row this plan exists to record would be silently absent from the
site's open-questions board. Verified against the committed bundle: it already drops `[OQ-101]`,
`[OQ-102]` and `[OQ-104]` for the same reason (19 questions parsed; 22 after the fix). The second
regex, `/OQ-(\d\d)/g` in the feature parser, is worse than absent — fed `OQ-105` it captures `OQ-10`
and links a feature to the wrong row. Recording a question the site swallows is not recording it, so
both regexes are fixed here. **Task 3 Step 5 states the count change explicitly** so the enlarged
`content.js` diff is expected rather than alarming.

**D3 — the amendment set is nineteen statements, not the fourteen the brief enumerates.**
The brief's list is design §1.1's, and design §1.1 is incomplete in one direction: `USER_ADD` leaving

GRANT SELECT, INSERT, UPDATE ON customer.customer_membership TO app_employee_role;

--   lets the caller choose which customer_membership it means.
CREATE FUNCTION customer.is_admin_of(account uuid, business uuid) RETURNS boolean
    LANGUAGE sql SECURITY DEFINER STABLE
    SET search_path = customer, pg_temp AS $$
    SELECT EXISTS (SELECT 1 FROM customer.customer_membership
                   WHERE account_id = account AND customer_id = business
                     AND role = 'admin' AND removed_at IS NULL) $$;

GRANT  EXECUTE ON FUNCTION customer.is_admin_of(uuid, uuid) TO app_customer_role;
